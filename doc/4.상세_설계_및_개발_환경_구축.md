### 이번 PoC 검증 범위

* 핵심 검증 대상: NoticeScanAgent (비정형 공고서 분석 파이프라인 완결성 검증)

* 입력 및 출력: (입력) 공고서 PDF/HTML -> (출력) ProcurementData 표준 JSON 구조체

* 최소 검증 대상: PpsAssistAgent (단일 비축모드 기반 단발성 질의 흐름)

* 제외 및 확장 범위: 멀티 agent_mode 동적 스위칭, 동적 요약 메모리, 스트리밍, 외부 웹 검색 등 운영 고도화 기능

* 성공 판정 기준: 지정 필수 필드 추출 정확도 70% 이상, 임의 추론(환각) 3건 미만, 포맷 준수율 80%이상

### 워크플로우 및 오케스트레이션 (Workflow & Logic)

* NoticeScanAgent이 비정형 조달 공고서에서 추출한 구조화된 JSON을 사용자가 Copy & Paste로 공고입력 화면에 입력.

* 공고입력 화면에서 법령 해석 또는 가이드문서의 확인이 필요한 부분은 PpsAssistAgent을 호출하여 답변 확인.

**2.1 처리 로직**

**[****NoticeScanAgent****]**

* **Step 1 (Input Analysis):** [사용자 의도 파악 방법 기술]\
  parse_document_node를 설계합니다. 파일 확장자를 판별하여 String 본문을 추출하되, 미지원 확장자나 빈 파일인 경우 예외를 캐치하여 status="failed" 상태를 기록하도록 설계합니다.

* **Step 2 (Tool Selection):** [도구 선택 기준 및 분기 처리 로직]\
  check_parsing_status 라우터 함수를 설계합니다. status 값이 정상(continue)이면 extract_metadata 노드로, 에러(error)면 error_handler 노드로 조건부 선형 분기하도록 정의합니다. 외부 도구 호출 없이 LangChain 프롬프트 체인을 다이렉트로 호출합니다.

* **Step 3 (Execution & Response):** [결과 통합 및 최종 답변 생성 방식]\
  structured_llm 체인을 설계합니다. llm.with_structured_output(ProcurementData) 방식을 채택하여 일반정보, 집행일정, 품목 등 필수 규격을 Pydantic 스키마 기반의 JSON 데이터로 한 번에 빌드하여 반환하도록 조율합니다. (단발성 처리, 스트리밍 미적용)

[**PpsAssistAgent****]**

* **Step 1 (Input Analysis):** [사용자 의도 파악 방법 기술]\
  query_rewrite_node를 설계합니다. 이전 문맥 결합을 배제한 단발성 질의 보강에 초점을 맞추며, 구어체 질문을 독립형 질의(contextual_query)로 재작성합니다.

* **Step 2 (Tool Selection):** [도구 선택 기준 및 분기 처리 로직]\
  로컬 LlamaIndex의 VectorStoreIndex를 직접 탐색하는 QnA_agent의 도구 생성하고 바인딩하도록 설계합니다.

* **Step 3 (Execution & Response):** [결과 통합 및 최종 답변 생성 방식]\
  검색된 컨텍스트와 시스템 프롬프트를 결합하여 최종 답변을 생성하며, 토큰 단위 스트리밍(`astream`) 응답을 클라이언트에 출력하도록 설계합니다.

**2.2 상태 관리**

* [대화 턴(Turn) 관리를 위한 상태 정의]\
  - **NoticeScanAgent State**\
  **-&#x20;**`file_path`, `document_text`, `extracted_data`, `is_violating`, `status`, `error_message` 필드로 구성되며 노드 실행 결과에 따라 `status` 값이 라우팅 분기 조건으로 사용되도록 구성\
  \
  - **PpsAssistAgent State**\
  **-&#x20;**`messages`, `file_full_path`, `convrstn_id`, `convrstn_details_id`, `question`, `queries`, `rag_answer` 필드로 구성하고, 노드 간 dict 반환값이 누적·병합(Reducer)되는 방식으로 공유

* - **NoticeScanAgent 그래프**\
  **-&#x20;**[Start] ──> parse_document ──> check_parsing_status (Router 판단)\
  ├── (정상 수렴) ──> extract_metadata ──> [End]\
  └── (파싱 에러) ──> error_handler ──> [End]\
  - **PpsAssistAgent 그래프**\
  **-&#x20;**[Start] ──> query_rewrite ──> local_rag_retrieval ──> generate_answer ──> [End]

**2.3 멀티 에이전트 확장 (Agent Mode & DB 기반 관리)**

* 각각의 에이전트(NoticeScanAgent, PpsAssistAgent)는 코드에 하드코딩하지 않고 PostgreSQL 테이블에서 조회하여 화면에 출력하고 사용자가 용도에 맞는 에이전트를선택할 수 있도록 제공합니다.

### 개발 환경 구축 및 재현 가이드

5. 검증 환경 기준\
   본 PoC는 **로컬 개발 환경(Windows/macOS) 구동 및 검증**을 기준으로 삼으며, 별도의 클라우드 서버 배포는 진행하지 않습니다.

6. 실행에 필요한 구성 요소 목록\
   1. **Python Runtime**: Python 3.12.x\
   2. Local Vector Storage: 로컬 파일 시스템 내 FAISS 인덱스 디렉터리\
   3. Database: Local PostgreSQL 16 (도메인 영속화 테스트용)
