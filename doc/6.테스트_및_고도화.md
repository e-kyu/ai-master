| 평가 대상 기능 | 5개 전문분야(일반용역/기술용역/시설공사/물품/비축) 법령·가이드 문서 기반 RAG 질의응답                                                                                                                                                                               |
| 평가 방식    | 조문·별표 근거가 필요한 실제 조달 상담 질문 샘플을 입력하여 검색된 근거 노드가 원문 조문·별표와 일치하는지 수동 검수                                                                                                                                                               |
| 평가 결과    | 항이 많거나 별표가 여러 페이지에 걸친 다단 채점표인 문서에서 parent 노드가 과도하게 커져, 질문과 무관한 문장까지 함께 검색되고 임베딩 유사도 기반 정렬 품질이 떨어지는 사례 확인                                                                                                                          |
| 개선 조치    | LawChunker에 parent 1200자·child 400자 크기 상한 적용, 항·소제목 단위 우선 분할 후 초과분만 문장 단위로 추가 분할, 조문·별표 구조가 감지되지 않는 문서는 FallbackChunker의 기본 Parent-Child 계층 청킹으로 전환, similarity_top_k=20으로 후보를 넓게 확보한 뒤 LLMRerank(top_n=2)로 법률 조문 간 선후관계를 반영해 재정렬 |
| 개선 후 결과  | parent 노드 크기가 일정 범위로 통제되어 무관한 문장이 함께 검색되는 사례가 줄었고, 재정렬 단계에서 조문 우선순위가 반영되어 최종 근거로 채택되는 노드의 관련성이 개선됨                                                                                                                                |

### 2-3. **[**&#xC870;달 상담 에이전&#xD2B8;**]**&#xC608;외 처리 및 가드레일

| 항목     | 내용                                                                                                                                     |
| ------ | -------------------------------------------------------------------------------------------------------------------------------------- |
| 차단 대상  | qna_doc/qna_law_base/qna_web_search 도구 호출 실패, 전문분야 분류(agent_mode) LLM 무응답·비정상 출력                                                       |
| 탐지 방식  | 각 도구 호출 노드에서 mcpUtils.call_tool 호출을 try/except로 감싸 예외를 감지하고, agent_mode 분류 노드에서는 LLM 응답이 없거나 문자열이 아닌 경우를 별도로 감지                        |
| 대응 로직  | 도구 호출 실패 시 status="failed"와 원인이 담긴 error_message를 반환해 파이프라인을 종료하고, agent_mode 분류가 실패하면 기본값 PpsStockpilingAgent로 폴백해 검색 자체는 중단되지 않도록 처리 |
| 테스트 결과 | 도구 호출을 강제로 실패시킨 테스트에서 `status=failed`와 원인 메시지가 정상적으로 반환되었고, agent_mode 분류 LLM이 무응답인 상황에서도 기본 전문분야로 폴백되어 파이프라인이 끝까지 완료됨을 확인             |

### 2-4. **[**&#xC870;달 상담 에이전&#xD2B8;**]**&#xAE30;타 문제 해결 사례

|        |                                                                                                                                                                                                                                                                         |
| ------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **항목** | **내용**                                                                                                                                                                                                                                                                  |
| 문제 상황  | 대화가 이어질수록 이전 질문·답변을 매번 그대로 프롬프트에 전달하면 "그거", "거기" 같은 대명사로 질의 의도가 불명확해지고, 주제가 완전히 바뀐 뒤에도 이전 맥락이 남아 있어 RAG 검색 품질을 떨어뜨리는 문제 발생                                                                                                                                              |
| 해결 방법  | convrstnContextUtils.get_convrstn_context에서 최근 대화 6건을 조회해 현재 질문과의 주제 연관성을 LLM으로 판별하고, 주제가 바뀌면 맥락을 공백으로 비우고 이어지면 topic/context/current_goal/status 형태로 요약해 저장, 이 요약본을 바탕으로 enhance_query_with_context에서 대명사를 실제 개체로 치환하고 상대 날짜(오늘/내일)를 절대 날짜로 변환한 질의문을 생성해 이후 RAG 검색에 사용 |
| 적용 결과  | 후속 질문에서도 이전 대화의 주체·시점이 유지된 채로 RAG 검색이 수행되고, 주제가 전환된 질문에서는 이전 맥락이 검색에 영향을 주지 않게 됨                                                                                                                                                                                        |
